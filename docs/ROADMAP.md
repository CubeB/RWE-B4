# Robot War Engine — Revival Roadmap

_Last updated: 2026-09-02. Status of the codebase is as of the `revival` integration branch (upstream `master` @ b2d8a31 + merged fork work, see Phase 0)._

## Where the project stands

- **Engine:** ~49k lines of C++20, deterministic fixed-point sim at 30 ticks/s, OpenGL 3 renderer, COB VM, A* pathfinding, lockstep multiplayer over the internet. Loads original TA data (HPI/GAF/3DO/COB/TDF/TNT/OTA).
- **Launcher:** Electron 22 / React 16 / Redux lobby + master server + `rwe_bridge` IPC.
- **History:** Michael Heasell (2017–2023, ~1,950 commits). Kevin Hake modernised the build in March 2026 (Boost removed, C++20, SDL3, CI green). Taylor Gunnoe added hotkeys / speed / pause / Phase‑1 AI in April 2026 (unmerged upstream until now).
- **Never had a stable release.** Only tag is `v0.1.0` (2017); the CMake version is derived from git tags.

## Guiding principles

1. **Determinism is load-bearing.** Anything that influences the sim lives in `sim/`, uses `SimScalar`/`simulation.rng`, no wall-clock or unordered iteration. Every merged feature must keep `rwe_test` and the `GameHash` sync checks green.
2. **Data-driven first.** TA data dictates UI screens and unit behaviour; prefer implementing what the FBI/TDF/GUI files already describe over inventing new config.
3. **Small, mergeable PRs against a green CI.** The March‑2026 CI matrix (gcc‑14, clang‑18, MSVC 2026, MinGW64, Debug+Release) is the gate.
4. **Personal project, for now.** No upstream coordination or outreach is planned. The forks by Kevin Hake, Taylor Gunnoe and Oskar Pedersen are reference material — check them before starting a feature so their work isn't redone.

**Matching the original.** A lot of Phase 1 has come from disassembling `TotalA.exe` rather than guessing at behaviour. The findings — addresses, constants, algorithms, and the places RWE deliberately differs — are consolidated in [`docs/TOTALA-EXE.md`](TOTALA-EXE.md), with the probe scripts that produced them in [`tools/exe/`](../tools/exe/). Aircraft *attack* behaviour — the mission table, the bomber run, the gunship pendulum — is in [`docs/TOTALA-EXE-MISSIONS.md`](TOTALA-EXE-MISSIONS.md). Read that before reimplementing anything that is meant to look or feel like TA; several plausible-sounding readings of this binary are wrong in ways that only show up when you replay the arithmetic.

- [x] **How the original orders what it draws** (disassembled from `TotalA.exe`, 2026-08-31). There is no depth buffer at the world level at all: TA is a pure 8-bit software painter and everything — terrain, units, features, shadows, particles — goes through the same three blit routines in call order, last one wins. The world render function is `0x468cf0`. Objects are bucketed by **world Z alone, quantised to 16 units** (`0x4697ed`), ignoring height entirely even though the projection is `screenY = z − y/2`; within a bucket there is no secondary sort. (`sortbias` is parsed from the FBI into `unitdef+0x21a` but read nowhere — dead in this build.) Particles are not in that list at all: they live in a separate manager with **ten hard-coded layer buckets**, and each SFX type is hand-placed in one — wakes on 2, weapon impacts on 6, **VTOL and thrust exhaust on 7**, damage smoke on 9 (over everything, including health bars). So particles are not uniformly in front or behind; each effect is placed by hand.
  **Why the Atlas exhaust sits under the aircraft in the original**: explicit layering, not depth and not the spawn position. Layer 7 is drawn at `0x469b38`, and the very next pass at `0x469b3d` draws every object whose `occupy != GROUND` — airborne units get their own late pass, so the aircraft is blitted over its own exhaust a few instructions later. Had it been on the ground the exhaust would have landed on top of it. RWE reaches the same result by a different route (depth testing against world Y, which is what its camera uses for depth); the two agree for an airborne aircraft, and differ only in that RWE will also let a tall ground unit in front occlude the plume, which TA would not. Judged the better behaviour for a renderer that has a real depth buffer, so kept.
- [x] **How the original does fog of war, and how terrain affects it** (disassembled from `TotalA.exe`, 2026-08-31). The grid is **32 world units per cell**, two heightmap samples across — which RWE already matches. Three states come from two arrays: one global *explored* array of `uint16` used as a bitmask, one bit per LOS group, set-only; and a per-player *visible* array of one byte per cell used as a **reference count** of how many of that player's units see it. `UpdateUnitLOS` (`0x4827b0`) runs per unit per tick but is **incremental** — it early-outs unless the unit changed cell (or, in terrain mode, moved its eye by more than 5), then subtracts the old stamp and adds the new one.
  Sight comes from FBI `SightDistance` (`unitdef+0x202`). There are three modes, exposed in the skirmish GUI as **Permanent / True / Circular**, defaulting to **True**. Circular mode does not ray-trace at all: it blits a hand-drawn mask sprite from `anims/vismasks.gaf`, ten frames of radius 5 to 14 cells, so sight is `clamp(SightDistance/32, 5, 14)` cells and saturates at 448 world units. True mode walks a **fixed fan of authored rays read from `gamedata/los.tdf`** (`TABLE1`..`TABLE9`, each a list of stepped `dx,dy` runs replicated into four quadrants) with a running maximum-slope horizon — shadow casting, not a per-cell retrace — and its radius is capped at **8 cells, 256 units**, because the table index is `min(sight/32, numtables-1)` with `numtables=9`.
  Terrain occlusion uses its own grid holding **two heights per cell**: `max(seaLevel, (2·max+min)/3)` decides whether a cell is *revealed* and `max(seaLevel, (max+2·min)/3)` decides whether it *occludes*, so it deliberately errs toward revealing. The eye is `clamp(unit Y, ≥ seaLevel+1) + the model's own height` (the maximum vertex Y of its 3DO, not an FBI field). The horizon is only raised on cells the ray actually revealed, so once a ray is blocked the horizon stops rising. Water is flat ground at its surface.
  **Radar has no grid at all** — it is a per-tick unit-versus-unit range query with `range = RadarDistance + 2 × altitude`, terrain never blocks it, and it flags units rather than revealing ground.

- [x] **Fog of war rebuilt to match the original** (2026-08-31).   Two things came back different from the plan, both for good reasons. The quadrant replication of the ray tables is **90° rotations, not sign flips**: measured on the real `los.tdf` at radius 8, rotations cover the disc exactly while sign flips leave ten holes along the east–west axis, and the tables are authored to tile that way (each fan's first ray runs up the +y axis and its last stops one cell short of +x). - [x] **Aircraft fly an arrival profile instead of bang-bang throttle** (disassembled from `TotalA.exe`, 2026-08-31). Construction aircraft rocked visibly while working. The fault was the velocity law, which ran full acceleration toward MaxVelocity outside the braking distance and full deceleration inside it. Traced tick by tick the step was pinned at exactly one acceleration on **every tick of every hop**, and on station the two branches chattered: `decelerate()` snapping to a dead stop set the braking distance to zero, so the next tick opened the throttle again, for the whole 150-tick hold. Bank is computed from change in velocity, so that chatter *was* the shake. - [x] AI frame stalls fixed (2026-08-30). `RWE_AI_PROFILE=1` times each AI pass and logs anything over 2 ms plus a 30 s summary — off by default and a pure observer, so it can never change what the AI does. What it found: `TransportManager::refreshExpansionSite` only honoured its 10-second cache when the last look had *found* something, so on a map with no metal across water it re-scanned the whole map three times a second — 1.2–1.5 s per call, dragging the sim from 30 ticks/s down to 7.8 on Painted Desert. It now respects the interval either way and does not look at all when every part of the map can be walked to. Also: `ReachabilityMap` labels the terrain's connected regions once per movement class and only re-homes on the base anchor afterwards (13.8 ms every 20 s → 0.005 ms); `chooseMexSite` walks a cached index of metal-patch cells instead of every cell out to the radius, visiting them in the same order so the site chosen is unchanged; `chooseBuildSite` does its cheap metal test before the footprint-walking `canBeBuiltAt`; `ThreatMap` clears only the cells it wrote and its scout-target predicate is only asked about cells that could still win. Coast To Coast: 33 spikes per 30 s → 1 (at load). Painted Desert: 82 spikes and a permanent quarter-speed stall → none, full 30 ticks/s.
- [ ] Cheaper terrain queries in the sim: `canBeBuiltAt` and `isGridPointWalkable` each walk a whole footprint (~30 grid reads per candidate), which is what makes AI site searches and the reachability labelling expensive. A cached per-cell slope and water-depth grid would speed up both.
- [ ] `EconomyManager::refresh` is now the AI's largest steady cost: it rescans every unit every tick with a string-keyed definition lookup each time. Not a spike, but it grows with unit count; making it incremental is the obvious next step.
